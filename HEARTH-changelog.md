# Hearth — Changelog

Detailed entries for the newest ~10 versions. Older entries live in `HEARTH-archive.md`.

**Do NOT read this file end to end at session start** — read only the entries for the versions you are actually touching. Architecture and working notes are in `HEARTH-notes.md`; pending work is in `HEARTH-backlog.md`.

## ✍️ How to write an entry (added 16/08/2026)

Entries here had grown to 500–2,800 words each, written by the most expensive model at the end of the longest context in the session — and the detail was already in the PR, which is permanent and searchable. New entries are capped:

- **A headline sentence** — what changed, and the date, in the existing bold style.
- **Up to ~150 words** of substance: the mechanism, the non-obvious decision, the test that pins it.
- **Every "do NOT simplify this into X" warning**, in full — these are the entries' real value and are exempt from the cap.
- **A link to the PR** for the full reasoning. Do not reproduce the PR body here.

If a change genuinely needs more (a shipped incident, a new subsystem), write the long version in its own doc and link it, as `HEARTH-freeze-analysis.md` and `HEARTH-global-search.md` already do.

## Recently completed (newest ~10 versions — older detailed entries live in `HEARTH-archive.md`)

- **v503: Golf one-hole view (04/10/2026).** Requested and designed by Cathal: a **Full card / One hole** switch above the scorecard totals. One hole shows a single hole card (par, SI, advantage label, both players' steppers, shots and points) with **‹ Prev · Hole N of M · Next ›** under it. The running totals box (strokes, to-par, Stableford for both) stays above. The choice is remembered per phone in `fl4_golf_view` (device-local UI state, not synced or backed up). One hole opens on `golfFirstOpenHole`, the first hole missing your score or the partner's, so a phone that slept resumes there. Next only moves; every tap still autosaves (v501). No auto-advance after scoring, as asked. **Tests:** `86-golf.js` extended.
- **v502: import a golf course from an AI chat (03/10/2026).** Requested and designed by Cathal the same day: **Import a course** sits in a new Golf header ⋯ sheet. It shows a copyable AI prompt (`golfImportPrompt`) asking for a `golf-course-v1` JSON (name, holes, pars, si, notes; one course or `{courses:[…]}`), a paste box (`stripPasteFence`), then a preview. Nothing is written until Import. `parseGolfCourseFile` is strict: a wrong par count, a par outside 3–6 or a bad stroke index is refused with the course and hole named, never coerced. **A course whose name matches a saved one (exact, ignoring case and spaces) is updated, the rest are added** (`golfImportPlan`). Two saved courses with that name are skipped, not guessed between. An update replaces holes, pars and SI (keeping the saved SI if the file has none), and replaces notes only if the file has some. Played rounds keep their snapshot. **Do NOT make the name match fuzzy** (the plants rule). No export, as agreed. **Tests:** `86-golf.js` extended, and `82-section-header-actions` now expects Golf's ⋯.
- **v501: Golf partner, handicaps and Stableford (03/10/2026).** Requested and designed by Cathal the same day: one optional partner per round, **playing** handicaps typed in (not index + slope), names and handicaps suggested from past rounds, and points on the scorecard and the rounds list (the best/average tiles stay strokes). Courses gain an optional **stroke index** per hole (`si`), all-or-nothing and each number once (`golfSiCheck`). `golfShots` spreads a handicap by SI (a 9-hole course uses the typed figure over SI 1–9; plus handicaps give shots back on the easiest holes). `golfPoints` is standard Stableford. A hole where one player gets more shots than the other is highlighted before any score goes in. Rounds snapshot `si` like `pars`; an old round picks up SI from its course when reopened, **never the pars. Do NOT widen that refresh to pars**, or a par edit rewrites a played score. **Autosave (asked the same day):** the round is written on its first score and on every tap after it, text fields on leaving them, and on `visibilitychange` when the screen sleeps. Done replaces Save and Cancel; the back button and header + save and leave without asking. **Do NOT bring back a Cancel that discards**: a score entered on the 3rd tee has to survive the phone sleeping until the 4th. **Tests:** `86-golf.js` extended, and `38-test-build-seed` checks the demo partner round.
- **v500: Golf section (03/10/2026).** Requested and designed by Cathal the same day: one golfer, hole-by-hole scores, saved courses with a par per hole, household-synced. New opt-in section ⛳ **Golf** (off by default). A course has a name, 9 or 18 holes and a par per hole; a round picks a course and scores each hole with −/+ steppers. The first tap on an empty hole lands on par, and − below 1 clears it. The list shows best and average (last 5) per round length, counting **complete rounds only**: a part-played round shows "thru N". One store, `fl4_golf`, with records of `kind` course or round (the Health shape). Whole-record newest-wins via `mergeGolfData`, with `fl4_tomb_golf`, on both channels, plus backup, restore and demo data. **A round snapshots its course's name, holes and pars. Do NOT turn that into a live course lookup**, or editing a course rewrites every score already played. No Home line, no global search. **Tests:** new `86-golf.js`; `01-boot-smoke`, `38-test-build-seed` and `82-section-header-actions` extended.
- **v499: Projects section (30/09/2026).** Designed 31/08/2026; Cathal answered the last three questions on 30/09/2026 (a task can be copied to To-do, no currency field, a fixed set of statuses) and built it in the same Opus session. New opt-in section 🔨 **Projects** (off by default): a project has a name, a status (**Idea · Planning · In progress · Done**, `PROJ_STATUSES`), a target date and notes. It holds typed items (task, quote, cost, contact, link; `PROJ_ITEM_FIELDS`). Detail shows tasks done, overdue tasks and the total spent (`applianceMoney`, euro). Store `fl4_projects`, household-shared on both channels, plus backup, restore, global search, `openRecord("projects", id)`, back-button discard and demo data. Home gets one self-suppressing line: open and overdue tasks across **Planning and In progress** projects only. **Merge is the Trips shape** (`mergeProjectsData`): project fields newest-wins, items by id with `fl4_tomb_projitems`. An item edit stamps the item only. **Do NOT flatten it to whole-record newest-wins**: a tick on one phone would undo a quote added on the other. **"Copy to To-do" is one-way** (`projSendTaskToTodo`): no link field on either side. **Do NOT turn it into a live link** without a fresh design call. **Tests:** new `85-projects.js`; `01-boot-smoke`, `38-test-build-seed` and `82-section-header-actions` extended for the new section.

- **v497: print a recipe (29/09/2026).** Requested and designed by Cathal the same day. He chose one recipe, and cooking essentials only. A 🖨 Print button between Edit and Delete on a recipe's page prints `recipePrintHtml(r, _recipeServings)`: the name, "Serves N" at the servings currently set (amounts scaled through `scaleIngredient`, exactly as on screen), ingredients with their sub-headings, prep (typed, or derived from the ingredients as on screen), the numbered method via `formatMethod`, and notes. Calories, category, source and the buttons are left off on purpose; the week plan was not asked for. **The print document now lives in one top-level `openPrintDoc(title, css, bodyHtml)`, which Lists Print uses too. Do NOT give a new print feature its own copy.** `tests/checks.sh` pins the single print-string DOCTYPE and the escaped `<\/script>`, and a literal `</script>` blanks the app. Test `83-recipe-print.js` stubs `window.open`.
